# 知客故障排查

排查时先保留现场，不要删除登录目录、业务数据或反复重发未知状态的评论。

## 双击后没有启动

**症状**：`启动.command` 没有打开，或 macOS 提示无法验证。

**检查**：

1. 确认使用 Mac Apple Silicon；`uname -m` 应输出 `arm64`。
2. 确认下载 ZIP 的 SHA-256 与发布页一致。
3. 在 Finder 中右键 `启动.command`，选择“打开”，不要用来源不明的脚本批量关闭系统安全检查。

**恢复验证**：终端显示知客正在启动，并自动打开 `http://127.0.0.1:8300`。

## 首次启动一直停在环境准备

**症状**：终端长时间显示正在安装依赖或下载浏览器。

**常见原因**：首次启动需要下载哈希锁定依赖和 Chromium；网络中断会导致失败。

**检查**：保留终端窗口，查看是否有明确下载进度或错误信息；确认当前网络可以访问 Python 包和 Playwright 下载源。

**恢复**：网络恢复后重新运行 `启动.command`。启动器只在环境指纹完整时标记准备完成。

## 提示 8300 端口被占用

**症状**：启动器明确提示端口 `8300` 被其他程序占用。

**处理**：先关闭旧的知客启动窗口。如果仍出现提示，检查是否有其他本机服务使用该端口；不要把其他服务误认为知客。

**恢复验证**：知客健康检查返回当前版本，启动器才会打开页面。

## 页面提示本地会话无效

**症状**：直接收藏或手动打开本机地址后，页面要求从启动窗口重新打开。

**原因**：每次启动都会生成新的本机会话凭据，旧标签页不会永久有效。

**恢复**：关闭旧页面，通过 `启动.command` 重新进入。

## 卡密无法激活

**症状**：提示卡密不存在、已过期、已停用或设备不匹配。

**检查**：确认完整复制卡密且没有多余空格；确认系统时间正常、网络可以访问授权服务。

**处理**：不要在 GitHub Issue 中粘贴卡密。通过[知客官网](https://zhike.crewup.cn/#buy)公布的联系方式，提供订单凭证和不含卡密的错误文字。

## 扫码登录没有成功

**检查**：确认扫码的是自己的抖音账号，登录窗口没有验证码、协议确认或平台风控提示。

**处理**：遇到验证码、异常验证或平台限制时停止自动化，先在官方界面完成人工确认。不要连续重复扫码或绕过平台提示。

## 没有生成拟回复

**常见原因**：

- 评论没有命中已配置的业务问答或 FAQ；
- 价格问题缺少明确 FAQ；
- 评论被识别为未知、敏感、广告或异常内容；
- 当前不在设定的北京时间活跃时段；
- 当日安全额度已经达到上限。

**恢复**：先查看跳过原因，再补充具体问答或调整合理的活跃时段。不要为了提高命中率配置过于宽泛的关键词。

## 发送结果显示“未知”

**处理**：不要重新发送。未知状态已经计入当日安全额度，需先到抖音官方页面人工确认评论是否实际发出，再在知客中处理账本状态。

## 需要备份或清除本机数据

数据管理中的导出与清除入口在未激活状态下也可用。清除是不可逆操作，应先导出备份并检查 ZIP 可正常打开；不要把备份上传到公开 Issue。

## 提交问题时提供什么

可以提供：

- 知客版本；
- macOS 版本与芯片类型；
- 可复现步骤；
- 去除个人信息后的错误文字或截图；
- 问题发生在激活、登录、预览还是发送确认阶段。

不要提供卡密、Cookie、二维码、账号登录目录、完整业务数据、授权响应或未脱敏日志。
